# Configuration Robustness & Tunability scope

## M0：反向参数搜索方案

用户于 2026-09-10 确认本方案。本轮优先开发参数配置鲁棒性，规模扩展性与
分布泛化性留到后续处理；七个评估维度的划分保持不变。

当前对象为 PyVRP 0.14.0 和 HiGHS 1.15.1。本项研究：在明确允许调整的
搜索参数范围内，能否找到使求解器相对默认配置明显退化的参数组合，
以及该退化是否能够重复观察到。

本项使用反向 SMAC3 搜索作为参数压力测试。自动搜索最优配置所对应的
可调优性，未在本项中定义独立评测协议。

## 已确认的设计

### 允许调整的范围

选择影响搜索策略的参数，并明确其允许取值和组合约束。候选配置应满足
求解器的合法参数要求；合法取值范围与本次希望覆盖的合理调整范围需要
分别核对。

比较时固定实例、输入表示、单次求解时间预算、线程数、运行环境、解的
合法性要求和精度要求。参数搜索不通过改变这些条件制造性能差异。

### 反向搜索

使用 SMAC3 提出参数组合，主动寻找相对默认配置退化更大的配置。
搜索允许多个参数共同变化，以寻找逐项变化可能遗漏的组合弱点。

候选配置与默认配置在同一批实例上运行，并按实例、solver seed 和求解
预算配对比较。沿用重复运行的要求，避免仅凭一次偶然很差的运行评价配置。
同一 seed 用于控制和配对运行，不保证改变搜索参数后随机选择或轨迹相同。

具体性能反馈、退化计算方式，以及实例和 seed 的汇总方式，留待正式协议
明确。本范围文档不指定公式或把全部搜索记录的 IQR 直接作为鲁棒性得分。

### 独立复测

对搜索找到的坏配置进行独立重复验证，检查退化是否可以复现。
保留搜索阶段与复测阶段各自的配置、运行结果、解、验证结果和失败记录。
复测安排及其与搜索所用实例、seed 的关系需要在运行实验前明确。

### 结果解释与代码版本比较

报告搜索过程中找到的最大性能退化及其具体参数配置，同时展示默认配置的
表现。搜索结果与独立复测结果分别呈现，不把搜索时观察到的极端值直接
当作已经复现的退化。

后续比较 Base 和 Agent 时，将双方搜索到的坏配置交叉用于两版代码评测。
两版的参数对应关系、参考配置和可比搜索条件需要在比较协议中明确。

找到可复现的坏配置，可以说明该求解器在指定条件下存在配置弱点。
没有找到坏配置，仅说明在声明的参数范围和搜索预算内尚未发现反例，
不构成全参数空间鲁棒性的保证。搜索找到的最大退化也不是已证明的全局最坏值。

## 实验前仍需明确

- 哪些搜索参数进入评测，其取值范围、组合约束和选择依据。
- PyVRP 与 HiGHS 分别使用什么性能反馈，如何计算和汇总相对默认配置的退化。
- 总搜索预算、搜索重复次数，以及独立复测的实例和 seed 安排。
- 缺解、异常退出、缺测和参数拒绝如何反馈给搜索器；完整原始记录始终保留。
- 比较 Base 与 Agent 时，默认配置、参数含义和搜索条件如何对应。

上述未定事项没有在本轮赋予默认值。本项不设退化验收阈值，不选择置信区间，
也不冻结统计量或版本。

## 后续实现约束

实现遵循仓库 [AGENTS.md](../../../AGENTS.md)：按功能组织代码，复用现有的
配置解析、求解器驱动、采集、独立验证和结果存储。同一功能模块内可以使用
不同求解器的类；不创建以求解器、问题或版本命名的专用实现文件。

本文件记录已确认的 M0 设计，尚不构成可执行的参数鲁棒性评测功能。
